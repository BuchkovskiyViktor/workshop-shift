.B.A.D.Workshop v5 — SERVER
============================

Это первая многопользовательская серверная версия.
Frontend: GitHub Pages (или другой HTTPS static hosting)
Backend/Auth/DB/Realtime: Supabase

ВАЖНО
-----
Данные локальной v4 НЕ переносятся автоматически в серверную v5.
Для теста с сотрудниками лучше начать с чистой базы.

ЧТО ИЗМЕНИЛОСЬ В v5
--------------------
1. Настоящие аккаунты сотрудников и руководителя.
2. Роль не выбирается в приложении.
   - каждый новый аккаунт создаётся как сотрудник;
   - доступ подтверждает руководитель;
   - роль руководителя назначается один раз через SQL Editor.
3. Общие данные между телефонами через Supabase.
4. Панель руководителя получает изменения через Realtime и дополнительно обновляется раз в минуту.
5. Тип смены выбирается:
   - при начале смены;
   - при создании нового участка смены.
   Отдельной кнопки «Тип смены» у сотрудника больше нет.
6. Вместо неё на рабочем экране кнопка «Дела».
7. To-do / Дела:
   - сотрудник создаёт собственные задачи;
   - приоритет высокий/обычный/низкий;
   - выполнение;
   - изменение порядка стрелками;
   - руководитель имеет общий список и может создавать задачи себе и сотрудникам.
8. Руководитель при проверке участка смены может изменить:
   - проект;
   - вид работы;
   - тип смены;
   - ставку за 10 часов именно для участка;
   - ставку переработки именно для участка;
   - добавить ответ на комментарий сотрудника.
9. Приватные заметки сотрудника хранятся в отдельной таблице с RLS и не читаются руководителем.
10. Расход сотрудника:
   - Личный транспорт
   - Такси
   - Обед
   - Закупки
   - Материалы
   - Парковка
   - Прочее
11. Руководитель видит каждый расход и при проверке назначает статью аналитики:
   - Транспорт
   - Обеды
   - Закупки
   - Материалы
   - Парковка
   - Аренда
   - Подрядчики
   - Прочее
   и подтверждает или отклоняет расход.
12. Оплата:
   - полная ставка = 10 часов;
   - до 10 часов пропорционально фактическому времени;
   - весь итог смены округляется до ближайших 15 минут;
   - после 10 часов считается переработка;
   - ставка переработки может быть общей, проектной или исправленной руководителем для конкретного участка.
13. Выплаты сотрудникам и остаток долга.
14. Доходы/сметы проектов.
15. Прямые затраты проектов.
16. Аналитика по мастерской, проектам и сотрудникам.

============================================================
ШАГ 1. СОЗДАЙТЕ SUPABASE
============================================================

1. Откройте https://supabase.com
2. Создайте новый Project.
3. Когда проект готов, откройте SQL Editor.
4. Скопируйте целиком содержимое файла:

   supabase-schema.sql

5. Нажмите Run.

Схема создаёт таблицы, RLS-права, регистрацию профилей и Realtime publication.

============================================================
ШАГ 2. ВСТАВЬТЕ ДВА ЗНАЧЕНИЯ В config.js
============================================================

В Supabase откройте Connect / API Keys и найдите:

- Project URL
- Publishable key

В config.js замените:

window.BAD_WORKSHOP_CONFIG = {
  supabaseUrl: 'PASTE_SUPABASE_PROJECT_URL_HERE',
  supabasePublishableKey: 'PASTE_SUPABASE_PUBLISHABLE_KEY_HERE'
};

на ваши значения.

НЕ вставляйте secret key / service_role key в сайт.

============================================================
ШАГ 3. ЗАМЕНИТЕ ФАЙЛЫ НА GITHUB PAGES
============================================================

В корне репозитория должны лежать:

index.html
app.js
config.js
manifest.webmanifest
service-worker.js
icon-192.png
icon-512.png

supabase-schema.sql и README.txt можно тоже хранить в репозитории, они не мешают.

Сделайте Commit changes.
После обновления GitHub Pages откройте сайт и обновите PWA.
Если старая версия закэшировалась, полностью закройте приложение и запустите ещё раз.

============================================================
ШАГ 4. СОЗДАЙТЕ АККАУНТ РУКОВОДИТЕЛЯ
============================================================

1. На сайте .B.A.D.Workshop нажмите «Регистрация».
2. Зарегистрируйте СВОЙ email и пароль.
3. Если Supabase попросит подтвердить email — откройте письмо.
4. После регистрации откройте Supabase -> SQL Editor.
5. Выполните, заменив email на свой:

update public.profiles
set role = 'manager', approved = true
where email = 'ВАШ_EMAIL';

6. Выйдите и снова войдите в .B.A.D.Workshop.

После этого откроется интерфейс руководителя.

============================================================
ШАГ 5. СОТРУДНИКИ
============================================================

1. Сотрудник открывает ваш адрес GitHub Pages.
2. Регистрируется своим email и паролем.
3. Видит «Ожидает подтверждения руководителя».
4. Руководитель: Люди -> Разрешить.
5. Руководитель задаёт тарифы сотрудника.
6. Сотрудник нажимает «Проверить доступ» или входит заново.

============================================================
ПРОВЕРКА НА ДВУХ ТЕЛЕФОНАХ
============================================================

Телефон 1 — руководитель.
Телефон 2 — сотрудник.

1. Руководитель создаёт проект.
2. Сотрудник начинает смену.
3. На телефоне руководителя сотрудник должен появиться в «Сейчас работают».
4. Сотрудник добавляет расход.
5. Руководитель открывает активную/завершённую смену и видит расход.
6. Сотрудник завершает смену.
7. Руководитель правит тип/ставку участка при необходимости.
8. Руководитель распределяет расходы по статьям и подтверждает их.
9. Руководитель подтверждает смену.
10. У сотрудника обновляются «Деньги».

============================================================
ПОКА НЕ ВКЛЮЧЕНО В v5
============================================================

- загрузка фотографий чеков;
- полноценная offline-очередь изменений при отсутствии интернета;
- push-уведомления;
- Excel/CSV экспорт;
- история всех правок как отдельный аудит-журнал.

Service Worker позволяет установленной оболочке PWA открываться после загрузки,
но изменения в серверных данных в этой версии лучше делать при наличии сети.
Эти функции логично добавлять после первого теста v5 реальными сотрудниками.
